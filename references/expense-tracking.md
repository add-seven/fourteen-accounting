# 记账细则与历史坑

SKILL.md 是行为准则的唯一来源；本文件补充细节、踩过的坑和排查步骤。两者冲突时以 SKILL.md 为准。

## 为什么不用 `expense_sync.py` 记带日期的账

`expense_sync.py` 的 CLI 只有 `<金额> <类型> <分类> <事项> [备注]`，**没有 `--date` 参数**。传 `--date 2026-08-08` 不会设日期：这个 token 会被塞进 `remark`，时间仍然取 `datetime.now()`。

- 记当天 → `expense_sync.py` 或 `expense_nl.py` 都行。
- 记过去的某天（`昨天` / `8月22日` / `周五`）→ 只能用 `expense_nl.py`，它负责换算日期。
- 已经写坏的记录 → `expense_ledger.py edit <ID> --date YYYY-MM-DD --remark ''` 修正，不要重新 INSERT（会烧掉 ID 并留下脏行）。

## 一句话多笔

拆分规则、分隔符与“不要拆成多次调用”的约束写在 SKILL.md 的记账要点里，此处不重复。这里只补一条边界：**只有每段都含数字时才拆**，所以 `午饭，加个鸡腿` 不会被拆坏；用空格或“和”连接的多笔仍算一笔。

## 分类词表维护

当前分类共 11 类（收入单列）：餐饮、交通、购物、数码、娱乐、居住、学习、医疗、通讯、烟酒、礼品。

- `数码` 覆盖电脑/键盘/显示器/手机/耳机/相机/路由器等；`手机话费`、`宽带费` 仍归 `通讯`，不会被“手机”“宽带”抢走。
- 匹配规则：最长关键词优先；长度相同按 `CATEGORIES` 的声明顺序。结果稳定可复现。
- 同一个关键词**不允许**出现在两个分类里（`tests.py` 会检查）；需要更精确时加更长的词，而不是依赖顺序。
- 改完词表后回填历史：`expense_ledger.py recat` 预览 → `recat --apply` 执行。默认只改“其他”。
- 快速验证单个词：`python3 -c "from expense_sync import auto_categorize; print(auto_categorize('充电线'))"`。

用户长期固定归类的项（可直接在记账时显式指定，避免每词都要加词表）：

| 事项 | 分类 |
|---|---|
| GPT / Claude / DeepSeek 订阅 | 学习 |
| 酷狗 / 网易云音乐 | 娱乐 |
| 蜜雪冰城 / 新品牌饮品 | 餐饮 |
| 中秋礼盒 / 月饼 / 花束 | 礼品（用户要求单列，不并入购物） |
| 烟 / 啤酒 / 白酒 | 烟酒 |
| 给亲人转账（如"奶奶200"） | 其他 |

## 报表为空怎么查

按顺序排查，不要先改数据：

1. 写账和看账必须指向**同一个** `EXPENSE_DB_PATH`，先确认这两条命令的环境变量一致。
2. 查目标日期实际有没有数据：`SELECT COUNT(*), SUM(amount) FROM expenses WHERE expense_time LIKE '2026-11-05%';`
3. 查库里 `MAX(id)` 是否符合预期；如果 ID 比印象里小很多，说明连的是旧副本。
4. 报表区间是 `[start, end)`，不含结束日；月报用 `YYYY-MM`，不要传 `2026-11-01`。
5. 定时任务里的脚本路径、skill 名称、数据库路径必须一致；本 Skill 是「十四记账」（`fourteen-accounting`），路径写错时任务会静默读到空上下文。
6. 日报/周报/月报统一走 `expense_report.py`（`--day` / `--week` / `YYYY-MM`）。它按**净支出**统计、已扣退款，不要另写脚本按毛额再算一遍，同一天同一笔账会得出不同数字，误判成“丢账”。

## 实体/项目维度比预想的少

回执里写了项目名、但 `summary --group project` 是空的，按顺序查：

1. 先看关联表有没有行：`SELECT COUNT(*) FROM transaction_projects;` 为 0 说明根本没写进去，不是统计问题。
2. 历史账（早期只记了文字、没有关联记录）用 `expense_ledger.py relink --start ... --end ...` 预览，确认列出的都是该补的账，再加 `--apply`。它只补缺的那一边，不动已有实体关联。
3. `relink` 的依据是**事项文本**，所以事项被改成“酒店”“买东西”这类无关键词的字样就补不出来，需要 `link <ID> --project '家庭自驾游'` 手工指定。
4. 项目预算 `spent` 为 0 时同理：先确认这笔有没有项目关联，再看 `budgets.period` 是否是当前月份。

## 疑似重复

`insight` 会按“同事项同金额同一天”列出疑似重复，但**不自动删**。确认是真重复后用 `expense_ledger.py delete <ID> --yes`（只删多记的那条，`--yes` 前先看预览）。阈值与更宽窗口的用法见 SKILL.md 的 `insight` 条目。

## 日期纪律

`expense_nl.py` 已处理 `今天/昨天/前天/大前天/周五/上周三/8月5日`。只有在**要向用户复述“今天是几号”**时才需要跑 `date`，不要用记忆或上文推断日期。
